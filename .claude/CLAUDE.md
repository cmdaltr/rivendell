# Rivendell — Project Context

## What this is

Rivendell is a unified DFIR platform — the merger of Elrond (analysis) and Gandalf (acquisition) into a single directed-graph execution model, with Eru as the AI analyst. It is Ben's primary professional tool, not a side project. Treat it accordingly.

## Architecture

```
Gandalf (acquisition) → Elrond (analysis) → Eru (AI analyst)
         ↓                      ↓                  ↓
  bash, Python, PowerShell  30+ forensic tools   Ask Eru (web) + ai CLI
  local, SSH, PSRemoting    Volatility 3, Plaso  Ollama (local LLM)
  order of volatility,      Artemis, RegRipper,  fixed answers from the
  SHA-256 log.meta          YARA, Sleuth Kit     case files without one
```

- **Execution model:** directed graph, not linear pipeline — conditional branching per OS, cloud provider, and evidence type (disk image, memory image, Gandalf archive, Mordor dataset, cloud logs)
- **Scale:** 50,000+ lines, 30+ integrated tools, 600+ MITRE ATT&CK techniques
- **Platform support:** Windows, Linux, macOS, AWS, Azure, GCP
- **Output:** case directory per job — `raw/` as collected, `cooked/` CSV and JSON per artefact, `analysis/`, `mitre_techniques.txt`, Plaso timeline, audit log
- **Pictures:** `docs/ARCHITECTURE.md`, and `rivendell map realm|elrond|gandalf|journey` (the 2D pages are generated by `scripts/docs/architecture/`: edit the generators, not the HTML; the 3D journey, `rivendell-journey.html`, is hand-written)

## Stack

- Python 3.12 in the worker and backend images; host-side scripts and Gandalf's Python collector stay Python 3.8-compatible
- FastAPI, SQLAlchemy and Alembic over Postgres (users, jobs, history); Redis + Celery for the job queue; case data in case directories on disk
- argparse for CLIs (`src/cli/rivendell.py`, `elrond.py`)
- openpyxl for XLSX output
- Volatility 3, Plaso (psteal), Artemis, RegRipper, YARA, The Sleuth Kit, ClamAV, ewfmount/qemu-nbd/apfs-fuse as subprocess calls
- Eru's LLM backend is Ollama (`OLLAMA_HOST`, `RIVENDELL_MODEL_NAME`, default `llama3.2:3b`); the CLI can also use llama.cpp through LangChain. No hosted-API backend exists
- React 18 front end; Docker Compose for everything (`docker-compose.yml`)

## Code conventions

- Type hints on all functions
- Docstrings on public functions and classes
- `pathlib` over `os.path`
- f-strings throughout
- Logging via the existing project logger in new code — do not add print statements. Gandalf's collectors and Elrond's existing modules print their progress by design; match the file you're in
- Error handling: raise specific exceptions, catch at the CLI boundary
- New forensic tool integrations: define the tool in `src/analysis/tools/definitions.py` and add its processing under `src/analysis/rivendell/process/` following the existing modules
- New artefact parsers (no external tool): a stdlib module in `process/extractions/` that returns rows, routed from `process/extra_artefacts.py` (or the OS router: `windows_artefacts.py`, `linux_artefacts.py`, `mac_artefacts.py`) into `cooked/<name>.csv`, techniques via `_record_techniques`; selection in `process/select.py` follows `is_extra_artefact`

## What Eru touches

Eru is the AI layer. It reads Elrond's case output and provides:
- Natural-language answers, case summaries and investigation suggestions (with Ollama)
- Fixed questions answered straight from the case files when Ollama or the model isn't available (`eru_offline.py`): hosts, ATT&CK techniques, persistence, logins, IOCs, suspicious commands
- ATT&CK mapping itself is Elrond's (`post/mitre/`), not Eru's

## Threat intelligence, collaboration, stacking

- Threat intelligence: `src/analysis/rivendell/threat_intel/` (Iran APT loader `iran_apt_loader.py`, STIX/TAXII, MITRESaw, matching, `enrich_artefact()` as the Eru-facing function); fixed 10-column schema: Evidential Element, Threat Group, Procedure Example, Technique ID, Technique Name, Tactic, Contextual Evidence, Reference URL, Navigation Layer URL, Source Type; table `threat_intel_indicators` — don't rename or restructure without asking. Elrond `--threatIntel`, API `/api/threat-intel`, the Intel page
- Case browser and collaboration: `src/web/backend/case_routes.py` + `case_files.py` (read-only over cooked/ and analysis/, never raw/), tables `case_findings`, `case_notes`, `case_hosts`, `case_activity`
- Stacking across hosts: `src/analysis/rivendell/analysis/stacking.py` (stdlib; run by `--Analysis` on 2+ hosts, rarity needs 3+ of an OS, Linux grouped by distro family); the isolation forest waits on a scikit-learn decision

## What not to do

- Do not rename Gandalf, Elrond, Eru, Aragorn, Andúril, Mordor or Pippin
- Do not restructure the execution graph model without explicit instruction
- Do not add new Python dependencies without checking `requirements/` (and `src/web/backend/requirements.txt`) first
- Do not convert subprocess tool calls to library imports — the subprocess boundary is intentional (isolation)
- Do not add print statements to new code — use the existing logger
- Do not change the database schema directly — add an Alembic migration
